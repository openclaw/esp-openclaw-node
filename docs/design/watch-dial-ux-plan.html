One OpenClaw.
Three shapes.

Watch, Dial and Tab5 select agents, resume conversations, control devices and show results. The screen and inputs change; the menu, features and ownership rules stay consistent. Tab5 is a five-inch touch panel, not a desk: it adds reach for a finger, not a second product.

The same five destinations

Agents, Conversations, Devices, Activity, Settings. One order on all three devices: five watch rows, one focused Dial entry, five large Tab5 rows. Tab5 also keeps Home, Conversations and Devices in a bottom bar, so Menu is a hub rather than the only door.

System state gets a small strip

Wi-Fi quality, OpenClaw link, battery. A working Wi-Fi connection does not mean the Gateway is online. Tab5 keeps the same strip at the right of its header, and anything that needs a sentence gets one in the screen body too.

Mono stays sparse

Values and short metadata use mono. Names and reading text stay proportional. Compact changes spacing, not font size; reading size is its own setting on every device, and on Tab5 it maps to 32–36 px so an em stays near 3 mm.

TAB5 / 1280 × 720 / 5-INCH CAPACITIVE TOUCH / LANDSCAPE

Five inches is small. Treat it that way.

Tab5 has more room than a watch and far less than a desk. At a nominal 11.564 pixels per millimetre a comfortable 9 mm target is 104 pixels, so the screen holds about four generous rows, or one readable transcript and one row of actions — and nothing else. This revision therefore drops the standing rail and the simultaneous list, detail and context columns. Every screen is one task: a header that says where you are, one reading zone, one action zone, and four destinations in the bar when you are standing on a destination. The scenes, copy and ownership rules are still exactly the ones the watch and the Dial read.

Three or four destinations, not six

Home, Conversations, Devices and Menu, in a bar that appears only when you are standing on a destination. Agents, Activity and Settings sit inside Menu, and the selected agent is also a tap target in the header wherever it is relevant. Everything deeper is opened by a row and left by Back, so context moves one way and the trail is always the real parent.

One task, one reading zone, one action zone

No rail, no list beside a detail beside an aside. A screen is a header, a scrollable reading zone with generous rows or a transcript, and a single action row whose primary is unmistakable. Voice, typing and handwriting are separate full-screen modes rather than controls crammed into a corner — a five-inch panel does not have a corner to spare.

Context travels with the thing it describes

Setup counts its five steps in the header crumb. The lamp’s owner, last reported value and request state sit under the control itself. An agent’s voice, text and microphone facts sit under the agent. Draft, pending, failed and reported stay as distinct states — a submitted request keeps its original agent and thread no matter where you navigate.

  • This geometry is a calculation, not a measurement. The vendor publishes a 5-inch 16:9 panel and a 128 × 80 × 12 mm enclosure; the active-area dimensions above are derived from the diagonal and the aspect ratio. Bezel, panel variant and tolerance will move them.
  • Nothing has been verified on hardware. No device, firmware or measurement was involved. Physical device proof is tracked separately and remains blocked.
  • No input beyond a finger is assumed. Hover, pen precision, multitouch gestures, pressure and physical keys are all out. Touch controller variants may differ in sampling rate, palm rejection and minimum contact area.
  • A browser cannot prove physical size. CSS millimetres are a 96 dpi convention, and device pixel ratio or screenshot resolution say nothing about a real monitor. Use the explorer’s sizing review with a physical ruler or an ID-1 card, and recalibrate after any zoom or display change.
  • Legibility still needs a hardware review. The type sizes above are chosen against the nominal density. At ≈ 293.7 ppi a simulator cannot establish that they read well in the room the device is actually used in.

The same journeys on all three devices.

First use
Identify device → protected setup → approve → first useful actionWi-Fi, Gateway approval and capability readiness are separate steps. All three devices work independently.
Resume work
Home → Continue → current conversation → result in ActivityKeep the selected agent and thread. Voice is an additional path on capable hardware.
Choose an agent
Menu → Agents → permitted agent → choose or create conversationKeep the old route until success. Existing controls, results and calls retain their owner.
Control a device
Devices → target → edit draft → Apply → Waiting → reported resultTouch and rotation share one action contract. Neither changing agent nor navigating away retargets a request.
Tune this device
Settings → Display → Compact / Comfortable or text size → previewSpacing and font size are separate. Devices → This device opens the same local control state.
Understand status
Status strip → Connection / Power → repair the failed layerOn the Dial, use Settings. On Tab5 the strip sits at the right of the header, and any state that needs a sentence also gets one in the screen body. Unknown battery is a dash; USB alone does not establish charging.
Reply on Tab5
Conversations → thread → transcript → Hold to talk or Write → keyboard / handwriting → review the draft → Send → replyTab5 only. Opening a thread replaces the list rather than sitting beside it, typing is its own full-screen step, and pending work keeps its original agent and thread. Voice, handwriting and keyboard are the same contracts as on the watch, not new ones.
Check a size
Sizing review → align a ruler or ID-1 card → calibrated physical mode → inspect targetsExplorer chrome, not device UX. One ratio drives the ruler, the samples and the device frame; the badge stays UNCALIBRATED until you confirm you measured, and resets when the display scale changes.
